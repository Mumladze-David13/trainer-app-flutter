# Задача: распознавание голосового набора тренировки из аудио (`POST /api/ai/parse-workout-audio`)

## Сервер
`http://144.31.189.154:8080` (NestJS + Prisma + PostgreSQL, тот же backend, что и в
остальных `backend_*_prompt.md`)

## Контекст и почему это нужно

`POST /api/ai/parse-workout` (см. `backend_voice_workout_parse_prompt.md`,
уже реализован) ожидал, что речь → текст происходит на устройстве
(`speech_to_text`, локально). На практике на части Android-прошивок
(проверено на Xiaomi/MIUI) системная служба распознавания речи, которую
обязано использовать любое стороннее приложение через публичный Android API
(`android.speech.SpeechRecognizer`/`RecognitionService`), либо отсутствует в
нормальном виде, либо игнорирует запрошенный язык и распознаёт случайный
набор английских слов вместо русской речи — независимо от языка интерфейса
телефона и настроек тренера. Это подтверждено: клавиатура (Gboard) и
приложения Google/Яндекс.Переводчик распознают ту же русскую речь корректно,
но они используют собственные встроенные движки, а не публичный системный
сервис — то есть это ограничение конкретных прошивок, а не то, что можно
исправить настройками телефона или кодом Flutter-приложения.

Решение: убрали `speech_to_text` из приложения полностью. Теперь тренер
просто записывает аудио на телефоне (пакет `record`, обычный `.m4a`/AAC,
16kHz моно) и голосовой файл целиком уходит на бэкенд — распознавание речи
(Speech-to-Text) и разбор на упражнения происходят там одним запросом.

Flutter-сторона (для справки, ничего здесь менять не нужно):
- `lib/core/services/api_service.dart` → `aiParseWorkoutAudio(File audioFile)` →
  `POST /ai/parse-workout-audio`, `multipart/form-data`, поле `audio` — файл
  `.m4a` (AAC-LC, 16kHz, моно, обычно до нескольких минут — тренер сам решает,
  когда закончить запись, ограничения по времени на клиенте нет).
  Ожидает **тот же формат ответа**, что и `/ai/parse-workout`:
  `res.data['exercises']` — `List` объектов `{ exerciseId?, name, sets, reps, weight }`.
- `lib/features/trainer/workout/voice_workout_input_sheet.dart` — сопоставление
  `exerciseId`/`name` с каталогом упражнений тренера и вся дальнейшая логика
  (проверка/правка перед вставкой в редактор) **не меняются** — они уже
  общие для текстового и аудио-пути (`_applyParsedExercises`).
- Ошибки (4xx/5xx/сетевые) не приводят к падению экрана — тренер видит
  сообщение и может добавить упражнения вручную кнопкой «Добавить», которая
  работает независимо от этого эндпоинта.
- Эндпоинт можно катить постепенно — форма/редактор тренировки уже полностью
  рабочие без него; пока эндпоинта нет, клиент получит понятную ошибку и
  вариант ввода текстом (см. ниже) продолжает работать при наличии
  `/ai/parse-workout`.

## `POST /api/ai/parse-workout-audio`

По аналогии с `parse-workout`: `@Roles(Role.TRAINER, Role.TRAINER_CLIENT)`,
`@UseGuards(JwtAuthGuard, RolesGuard)`, тот же контроллер `src/ai/ai.controller.ts`.
Принимает `multipart/form-data` (не JSON) — `@UseInterceptors(FileInterceptor('audio'))`
(NestJS + `multer`, как обычно для загрузки файлов в этом стеке, если такой
паттерн уже используется где-то ещё в проекте — например для фото — следуйте
тому же способу подключения `multer`).

### Ограничения на файл
- Принимать `audio/*` (реальный MIME от клиента — `audio/mp4`/`audio/aac` для
  `.m4a`, конкретное значение зависит от того, что подставляет Dio/`record` —
  не валидировать строго по MIME, полагаться на расширение/успешную
  транскрипцию).
- Ограничить размер файла (например 20MB — с запасом на несколько минут
  16kHz-моно AAC, это исчезающе мало по размеру) через стандартный лимит
  `multer` (`limits: { fileSize: ... }`) — при превышении `413`.
- Пустой/отсутствующий файл — `400`.

### Логика (`AiService.parseWorkoutAudio`)
1. Лимит токенов — та же проверка, что в `parseWorkout`
   (`getOrCreateSettings(trainerId)`, `PLAN_TOKEN_LIMITS[settings.plan]`, `403`
   при исчерпании). Если есть смысл учитывать стоимость транскрипции отдельно
   от токенов LLM — можно завести отдельный простой счётчик для API
   распознавания речи (см. пункт про стоимость ниже), но это не обязательно
   для первой версии — достаточно того же общего AI-лимита тарифа.
2. **Транскрипция аудио → текст**: сначала попробовать переиспользовать уже
   настроенного провайдера, если он есть (например, если `AiGateway` уже
   заведён поверх Anthropic — у Claude нет своего STT API, значит для этого
   шага нужен отдельный провайдер). Рекомендация — **OpenAI Whisper API**
   (`POST https://api.openai.com/v1/audio/transcriptions`, модель `whisper-1`
   или новее `gpt-4o-transcribe`/`gpt-4o-mini-transcribe`, если уже
   используются) — стабильно хорошее качество на русском, дёшево
   (~$0.006/мин у `whisper-1`), простой REST-вызов с `multipart/form-data`
   и полем `language: 'ru'` для подсказки языка. Нужен отдельный API-ключ
   (`OPENAI_API_KEY` в `.env`, по аналогии с `ANTHROPIC_API_KEY`) — если его
   ещё нет, завести и передать значение отдельно (не в этом файле, через
   защищённый канал).
   - Если в проекте уже есть какой-то другой настроенный STT-провайдер
     (Yandex SpeechKit и т.п.) — можно использовать его вместо Whisper, схема
     ниже не завязана на конкретного провайдера, только на то, что на выходе
     получается обычный русский текст.
3. Дальше — **1:1 та же логика**, что в `parseWorkout` из
   `backend_voice_workout_parse_prompt.md`, начиная с шага 2 (загрузка
   каталога упражнений тренера, тот же системный промт Claude, тот же вызов
   `this.gateway.complete(...)`, та же валидация `exercises`, тот же формат
   ответа). **Не дублировать эту логику** — вынести общую часть в приватный
   метод (например `parseWorkoutText(trainerId, text)`), который дергают и
   `parseWorkout`, и `parseWorkoutAudio` после транскрипции.
4. Учёт токенов/использования — `AiUsageLog.create` с `operation:
   'parse_workout_audio'` (отдельная операция от `parse_workout`, чтобы в
   `GET /ai/usage` было видно, сколько запросов пришло голосом), либо второй
   записью, если транскрипция и разбор считаются раздельно по стоимости —
   на усмотрение реализующего, не критично для клиента.
5. Ответ — **та же форма**, что у `parse-workout`:
   `{ exercises: [...], usage: { totalTokens, costUsd } }`. Полезно (но не
   обязательно для клиента) дополнительно вернуть `transcript: string` —
   сырой распознанный текст, для отладки/логов на бэкенде.
6. Если транскрипция вернула пустую строку/бессмыслицу (например тренер
   ничего не сказал или запись пустая) — не вызывать Claude зря, сразу
   `BadRequestException` с понятным сообщением
   (`'Не удалось распознать речь в записи. Попробуйте ещё раз.'`) — клиент
   покажет его в блоке ошибки как есть или обобщённо (см. Flutter-код выше).

## Как проверить

1. `POST /api/ai/parse-workout-audio` с реальной записью голоса на русском
   (`multipart/form-data`, поле `audio`, файл `.m4a`) под JWT тренера — `200`,
   `exercises` содержит разумные позиции.
2. Тишина/шум без речи в записи — `400` с понятным сообщением, не `500`.
3. Файл без JWT — `401`. Роль `CLIENT` — `403`.
4. Слишком большой файл — `413`.
5. Исчерпанный лимит токенов тарифа — `403`, как у `parse-workout`.
6. `GET /api/ai/usage` после вызова — новая запись учтена в статистике месяца.
7. Убедиться, что `parse-workout` (текстовый, старый) продолжает работать без
   изменений — общая логика должна быть вынесена в переиспользуемый метод, а
   не скопирована с риском разъехаться.

## Затронутые файлы

- `src/ai/ai.controller.ts` — новый `@Post('parse-workout-audio')` с
  `@UseInterceptors(FileInterceptor('audio', { limits: {...} }))`.
- `src/ai/ai.service.ts` — новый метод `parseWorkoutAudio` (транскрипция +
  вызов общей приватной логики разбора текста, вынесенной из существующего
  `parseWorkout`), новая интеграция с STT-провайдером (Whisper API или
  аналог).
- `.env` / секреты — новый `OPENAI_API_KEY` (или ключ выбранного
  STT-провайдера), если ещё не заведён.
- Зависимости — при использовании Whisper API можно обойтись обычным
  `fetch`/`axios` с `FormData` (Node 18+/`undici`), отдельный SDK не
  обязателен.
