# Задача: распознавание голосового набора тренировки (`POST /api/ai/parse-workout`)

## Сервер
`http://144.31.189.154:8080` (NestJS + Prisma + PostgreSQL, тот же backend, что и в
остальных `backend_*_prompt.md`)

## Контекст

Тренер во время занятия надиктовывает состав тренировки голосом вместо
построчного ручного ввода в редакторе. Flutter-сторона уже реализована (в этой
сессии) под контракт ниже — реализовать нужно 1:1, не меняя. Речь → текст
происходит целиком на устройстве (`speech_to_text`, локально, без сервера) —
на бэкенд уходит уже готовый русский текст, который нужно разобрать в список
упражнений с подходами/повторами/весом. Это тот же класс задачи, что и
`POST /api/ai/parse-meal` (`src/ai/ai.service.ts` → `parseMeal`) — свободный
текст в строгий JSON через Claude, тот же лимит токенов по тарифу — но с
одним отличием: подбор `exerciseId` нужно делать так же, как в
`POST /api/ai/generate-program` (`src/ai/ai.service.ts:65-110`) — передавать
Claude каталог упражнений тренера в промте и просить вернуть `id` из этого
списка, а не только текстовое название.

Flutter-сторона (для справки, ничего здесь менять не нужно):
- `lib/core/services/api_service.dart` → `aiParseWorkout(String text)` →
  `POST /ai/parse-workout` с телом `{ "text": text }`, ожидает `res.data['exercises']`
  как `List` объектов `{ exerciseId?, name, sets, reps, weight }`.
- `lib/features/trainer/workout/voice_workout_input_sheet.dart` — если в ответе
  для позиции есть `exerciseId` и он реально есть в каталоге упражнений,
  который уже загружен на клиенте (`getExercises()`) — используется он;
  если `exerciseId` отсутствует или не совпал ни с одним — клиент сам
  делает локальный фаззи-матч по `name`, а если и это не помогло — тренер
  выбирает упражнение вручную в экране проверки перед вставкой в редактор.
  То есть **ошибка сопоставления на бэкенде не критична** — просто верните
  `exerciseId: null` и осмысленный `name`, если уверенности в конкретном
  упражнении каталога нет — не придумывайте id.
- Ошибки (4xx/5xx/сетевые) не приводят к падению экрана — тренер просто
  видит сообщение и может добавить упражнения вручную кнопкой «Добавить»,
  которая работала и до этой задачи. Эндпоинт можно катить постепенно —
  форма/редактор тренировки уже полностью рабочие без него.

## `POST /api/ai/parse-workout`

По аналогии с `parse-meal`: `@Roles(Role.TRAINER, Role.TRAINER_CLIENT)`,
`@UseGuards(JwtAuthGuard, RolesGuard)`, тот же контроллер `src/ai/ai.controller.ts`.

### DTO — `src/ai/dto/workout-ai.dto.ts` (новый файл, по образцу `meal-ai.dto.ts`)
```ts
export class ParseWorkoutDto {
  @IsString()
  @IsNotEmpty()
  text: string;
}
```

### Логика (`AiService.parseWorkout`, по образцу `parseMeal` + `generateProgram`)
1. Лимит токенов — та же проверка, что в `parseMeal`/`generateProgram`
   (`getOrCreateSettings(trainerId)`, `PLAN_TOKEN_LIMITS[settings.plan]`,
   `403` при исчерпании).
2. Загрузить каталог упражнений — **тот же запрос**, что в `generateProgram`
   (`this.prisma.trainerExercise.findMany({ select: { id: true, name: true },
   orderBy: { name: 'asc' } })`), собрать `exerciseList` той же строкой
   `- ${e.name} (id: ${e.id})`.
3. Системный промт Claude:
   ```
   Ты ассистент тренера, разбирающий голосовую надиктовку состава тренировки
   на структурированный список упражнений.

   Вот каталог упражнений тренера — используй exerciseId ТОЛЬКО из этого
   списка, если упражнение из текста ему соответствует:
   <exerciseList>

   Если упражнения из текста нет в списке или ты не уверен в соответствии —
   верни exerciseId: null и осмысленное название из текста, НЕ выдумывай id.

   Отвечай строго в JSON формате без лишнего текста, markdown или пояснений.
   Формат ответа:
   {
     "exercises": [
       {
         "exerciseId": "id из списка или null",
         "name": "название упражнения",
         "sets": число_подходов,
         "reps": число_повторов_в_подходе,
         "weight": вес_в_кг_число_или_null
       }
     ]
   }

   Правила:
   - Если в тексте несколько упражнений — верни несколько элементов.
   - sets/reps — если явно не названы, оцени разумные значения по контексту
     (например "жим лёжа на восьмидесяти" без числа подходов — подставь 3).
   - weight — только если явно назван в тексте (число + "кг"/просто число
     рядом с упражнением), иначе null — не выдумывай вес.
   - Числительные могут быть словами ("три подхода по десять") — разбирай их
     как числа.
   ```
4. Вызов через `this.gateway.complete(systemPrompt, text)` — тот же `AiGateway`,
   что и в `parseMeal`/`generateProgram`, не создавать новый клиент.
5. Учёт токенов — `AiUsageLog.create` с `operation: 'parse_workout'`, как в
   `parseMeal` (`operation: 'parse_meal'`).
6. Разобрать `text` ответа (снять ```json``` обёртку, `JSON.parse`), при
   ошибке парсинга — `BadRequestException('AI вернул некорректный формат.
   Попробуйте ещё раз.')`, как в `parseMeal`.
7. Валидация каждого элемента `exercises`: `sets`/`reps` — положительные целые,
   `weight` — либо `null`, либо положительное число; `exerciseId`, если не
   `null`, должен реально присутствовать в `exerciseList` из шага 2 — если
   Claude всё-таки что-то придумал, подменять на `null`, а не отдавать
   клиенту несуществующий id (клиент не перепроверяет).
8. Ответ: `{ exercises: [...], usage: { totalTokens, costUsd } }` — форма
   `usage` такая же, как в `parseMeal`, Flutter её игнорирует, но пусть будет
   для консистентности с остальными AI-эндпоинтами и `GET /ai/usage`.

## Как проверить

1. `POST /api/ai/parse-workout` с `{"text": "жим лёжа три подхода по десять на
   восьмидесяти, потом присед сто на пять раз четыре подхода"}` под JWT
   тренера — `200`, `exercises` содержит 2 позиции с разумными `sets/reps/weight`.
2. Если в каталоге тренера есть упражнение с похожим названием — `exerciseId`
   в ответе соответствует реальному `id` из `TrainerExercise`.
3. Текст с упражнением, которого точно нет в каталоге (например случайный
   набор слов) — `exerciseId: null`, `name` — что-то осмысленное, `200`, не
   `500`.
4. Пустой текст — `400` (валидация DTO). Без JWT — `401`. Роль `CLIENT` —
   `403` (не входит в `@Roles`).
5. Исчерпанный лимит токенов тарифа — `403`, как у `parse-meal`.
6. `GET /api/ai/usage` после вызова — новая запись с `operation: 'parse_workout'`
   учтена в статистике месяца.
