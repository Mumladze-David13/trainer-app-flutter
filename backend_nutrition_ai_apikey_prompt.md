# Задача: включить ANTHROPIC_API_KEY на проде для nutrition-AI эндпоинтов

## Сервер
`http://144.31.189.154:8080` (NestJS + TypeORM + PostgreSQL, тот же backend,
что и в остальных `backend_*_prompt.md`)

## Статус на 2026-08-04

4 новых эндпоинта питания (`/api/ai/parse-meal`, `/api/ai/log-meal`,
`/api/ai/generate-meal-plan`, `/api/ai/save-meal-plan`) задеплоены, контракт
сверен с Flutter-клиентом построчно и совпадает 1:1 — Flutter-сторона
полностью готова (`lib/features/nutrition/ai_meal_plan_screen.dart`,
`ai_meal_quick_add_sheet.dart`, `api_service.dart`), менять там ничего не
нужно.

Единственный блокер: `parse-meal`/`generate-meal-plan` отвечают
**`500 Internal Server Error`** — по докладу с бэкенд-стороны, на сервере не
задан `ANTHROPIC_API_KEY`. Я прощупал эндпоинт без авторизации — роут
существует (`401` на запрос без токена), но подтвердить сам факт отсутствия
ключа не могу — нужен реальный запрос с валидным JWT, которого у меня нет.

## Что сделать

1. **Сначала проверить, не шире ли проблема**, чем "ключа нет": в проекте уже
   есть *другой* рабочий AI-функционал — генерация программы тренировок
   (`POST /api/ai/generate-program`, экран `GenerateProgramScreen`), который
   тоже дергает Claude. Если он **сейчас в проде работает** — значит
   `ANTHROPIC_API_KEY` где-то в окружении уже есть, и дело не в отсутствии
   ключа, а в том, что новый код (`src/ai/ai.service.ts`, судя по
   sync-промпту от бэка) читает его из другого места/неправильного
   env-имени/не того `ConfigModule`-скоупа. Если генерация программы **тоже
   не работает** — ключ действительно отсутствует целиком.
   - Быстрая проверка живьём: открыть приложение → трener → клиент → "AI
     Генератор программ" → сгенерировать. Или curl с валидным токеном на
     `/api/ai/generate-program`.

2. **Найти, где сервер должен брать ключ**:
   - SSH на сервер, найти процесс backend (`pm2 list` / `docker ps` /
     `systemctl status trainer-backend` — как окажется поднято).
   - Найти `.env` (или `docker-compose.yml`/systemd unit с `Environment=`),
     который реально подхватывается процессом — не в репозитории, а на
     самом сервере (в репо ключа быть не должно, secrets не коммитятся).
   - Проверить точное имя переменной, которое ждёт код:
     `grep -r "ANTHROPIC_API_KEY\|CLAUDE_API_KEY" src/` в backend-репо —
     убедиться, что имя в `.env` совпадает 1:1 с тем, что читает
     `ai.service.ts` (и, если есть, `.env` для generate-program — вдруг там
     другое имя переменной, отсюда и расхождение).

3. **Добавить/поправить переменную и перезапустить процесс**
   (`pm2 restart <app>` / `docker restart <container>` /
   `systemctl restart trainer-backend` — смотря что используется), чтобы
   новое значение окружения подхватилось.

4. **Проверить, что фикс сработал**, до того как звать меня обратно на
   ручное тестирование:
   ```bash
   curl -X POST http://144.31.189.154:8080/api/ai/parse-meal \
     -H "Authorization: Bearer <валидный_токен>" \
     -H "Content-Type: application/json" \
     -d '{"text": "гречка с курицей 250г"}'
   ```
   Ожидается `200` с `items`/`usage`, а не `500`.

## После фикса

Дать знать — я прогоню оба флоу на подключённом телефоне (Redmi Note 10):
- `AiMealQuickAddSheet`: текст → распознавание → правка позиции → сохранение
  → приём пищи появляется в дневнике.
- `AiMealPlanScreen`: генерация меню на день → сумма `totals.calories`
  сопоставима с `targetCalories` из профиля → сохранение → меню появляется
  в дневнике на нужную дату.
- 403 при исчерпанном лимите токенов на обоих экранах.
- Отдельно — что возвращает `generate-meal-plan`, если у клиента вообще нет
  `nutrition_profiles` (этот путь на бэке не специфицирован явно).

Если что-то разойдётся с контрактом — оформлю как отдельный
`backend_*_fix_prompt.md`, как уже делалось для
`backend_nutrition_fix_prompt.md`.
